## 1. مقدمة

### 1.1 الغرض
الغرض من هذه الوثيقة وصف المتطلبات الوظيفية وغير الوظيفية لمنصة Deal One، علشان تكون مرجع مشترك للفريق (المطورين، والتصميم، والدعم، والإدارة) قبل بدء التنفيذ وأثناءه وبعد الإطلاق.

### 1.2 نطاق المنتج
Deal One منصة إعلانات مبوبة تعمل على الموبايل (Android وiOS)، تتيح للأفراد والشركات ومنافذ البيع رفع إعلانات بيع أو شراء أو إيجار أو خدمات، في ستة أقسام رئيسية:

1. العقارات
2. مواد البناء والكهرباء
3. الخدمات (مكاتب هندسية وخدمات منزلية)
4. الأجهزة المنزلية والديكور
5. السيارات (بيع، شراء، قطع غيار، صيانة)
6. الملابس والإكسسوارات

### 1.3 الأهداف
- ربط المعلن بالمهتم بسرعة، مع تواصل واضح.
- منح الشركات حرية اختيار طريقة البيع (دفع أونلاين أو تواصل).
- بحث دقيق بالقسم والمنطقة والموقع الجغرافي.
- حماية المنصة من السبام والحسابات الوهمية.
- تحكم كامل للإدارة في الحدود والموافقات والإعدادات.

### 1.4 خارج النطاق (النسخة الأولى)
- الدفع أونلاين وإدارة الطلبات (المرحلة الثالثة).
- الاشتراكات المدفوعة للشركات (المرحلة الثالثة).
- التقييمات والمراجعات (المرحلة الثالثة).
- تطبيق منفصل للشركات (قرار معلق).
- الإعلانات المدفوعة والترويج (غير مخطط حالياً).

### 1.5 التعريفات والاختصارات
| المصطلح | المعنى |
|---|---|
| المستخدم | أي شخص مسجل في المنصة |
| حساب البيع (Account) | كيان يرفع الإعلانات، ممكن يكون فرد أو شركة أو مصنع أو مكتب أو منفذ |
| الإعلان (Listing) | عرض بيع أو شراء أو إيجار أو خدمة |
| القسم (Category) | تصنيف رئيسي أو فرعي للإعلان، وله حقول خاصة |
| طريقة البيع | `دفع أونلاين` أو `تواصل`، ويحددها الحساب |
| قناة التواصل | `داخل التطبيق` أو `خارجي`، ويحددها البائع لكل إعلان |
| الحد اليومي (Quota) | عدد مسموح من عملية معينة في اليوم، ويحدده الأدمن |
| الدعم | فريق مراجعة الإعلانات والحسابات |
| الأدمن | المدير الذي يدير الإعدادات والأدوار |
| Turnstile | خدمة التحقق من Cloudflare |
| MVP | الحد الأدنى من المنتج القابل للإطلاق |

### 1.6 المراجع
- السيستم ديزين: Deal_One_System_Design.md
- Cloudflare Turnstile documentation
- Firebase Cloud Messaging documentation

## 2. الوصف العام

### 2.1 منظور المنتج
Deal One نظام جديد بيتكون من:
- تطبيق موبايل (المستخدم النهائي).
- Backend API (المنطق كله).
- WebSocket للشات الفوري.
- لوحة إدارة ويب (للدعم والأدمن).
- قواعد بيانات وتخزين وخدمات خارجية (Cloudflare، Redis، FCM، PostgreSQL، التخزين السحابي).

### 2.2 وظائف المنتج الرئيسية
- التسجيل والدخول بالتحقق.
- إنشاء حسابات البيع وإدارتها.
- رفع الإعلانات ومراجعتها ونشرها.
- البحث والفلترة.
- التواصل بالشات أو خارج التطبيق.
- إدارة الحدود اليومية من الأدمن.
- الإشعارات.

### 2.3 أنواع المستخدمين
| النوع | الوصف | الصلاحيات الأساسية |
|---|---|---|
| زائر | غير مسجل | التصفح والبحث وعرض الإعلانات |
| مستخدم مسجل | حساب شخصي | كل صلاحيات الزائر + الشات + إنشاء حساب بيع |
| صاحب حساب بيع | مستخدم عنده حساب بيع أو أكتر | إدارة الإعلانات والفروع وطريقة البيع |
| دعم | موظف مراجعة | موافقة ورفض الإعلانات، التحقق من الحسابات |
| أدمن | مدير النظام | كل صلاحيات الدعم + الحدود والإعدادات + الأدوار |

### 2.4 بيئة التشغيل
- **الموبايل:** Android 9 فما فوق، وiOS 15 فما فوق.
- **الويب (لوحة الإدارة):** المتصفحات الحديثة (Chrome، Edge، Safari، Firefox).
- **الباك إند:** بيئة سحابية، مع Redis وPostgreSQL.
- **الشبكة:** اتصال إنترنت (3G فما فوق للاستخدام الأساسي).

### 2.5 قيود التصميم
- التطبيق يدعم العربية كلغة أساسية، مع دعم RTL كامل.
- التوقيت الرسمي للمنصة: توقيت القاهرة (`Africa/Cairo`)، مع مراعاة التوقيت الصيفي.
- العملة: جنيه مصري.
- الخصوصية: التزام بقانون حماية البيانات الشخصية المصري.

### 2.6 الافتراضات
- المستخدم عنده هاتف ذكي وحساب بريد أو رقم موبايل مصري.
- الشركات عندها وثائق رسمية (سجل تجاري أو ما يعادله).
- الدعم متاح يومياً للمراجعة في ساعات محددة.
- Cloudflare Turnstile و FCM متاحين ومدعومين في مصر.

## 3. المتطلبات الوظيفية

> ترميز المتطلبات: `FR-<الوحدة>-<رقم>`. كل متطلب له أولوية: **Must** (ضروري للنسخة الأولى)، **Should** (مهم)، **Could** (اختياري).

### 3.1 التسجيل والمصادقة (AUTH)

| ID | المتطلب | الأولوية |
|---|---|---|
| FR-AUTH-001 | يقدر المستخدم يسجل بالرقم المحمول عبر OTP | Must |
| FR-AUTH-002 | يقدر المستخدم يسجل بالإيميل وكلمة المرور | Must |
| FR-AUTH-003 | يتطلب التسجيل التحقق بـ Turnstile قبل إرسال OTP أو إنشاء الحساب | Must |
| FR-AUTH-004 | يتطلب تسجيل الدخول التحقق بـ Turnstile | Must |
| FR-AUTH-005 | الـ OTP صالح لمدة 5 دقايق، ويتحاول 5 مرات كحد أقصى | Must |
| FR-AUTH-006 | الـ access token صالح 15 دقيقة، والـ refresh token صالح 30 يوم | Must |
| FR-AUTH-007 | يقدر المستخدم يشوف كل الأجهزة المسجلة ويخرج منها | Should |
| FR-AUTH-008 | عند تغيير كلمة المرور، كل الجلسات تتلغي إلا الحالية | Must |
| FR-AUTH-009 | يقدر المستخدم يستعيد كلمة المرور عبر الإيميل أو OTP | Must |
| FR-AUTH-010 | كلمات المرور تتخزن مشفرة (bcrypt أو Argon2) | Must |

| FR-USR-003 | يقدر المستخدم يحذف حسابه، والبيانات تتحذف أو تتجهل حسب سياسة الخصوصية | Must |

| FR-ACC-002 | يقدر المستخدم يكون عنده أكتر من حساب بيع | Must |

| FR-ACC-005 | عند تغيير طريقة البيع لدفع أونلاين، الإعلانات بدون سعر ثابت تتخفي من الدفع لحد ما تتعدل | Must |

## 8. معايير القبول

### 8.1 معايير القبول للنسخة الأولى
النسخة الأولى تعتبر مقبولة لما:
1. كل المتطلبات بأولوية **Must** مكتملة ومختبرة.
2. مفيش عيوب حرجة (Critical) مفتوحة.
3. اختبار الحمل بيحقق أهداف الأداء في القسم 4.1.
4. المراجعة الأمنية خلصت بدون مشاكل حرجة.
5. دليل الدعم والإدارة متاح.
6. الدعم والأدمن اتدربوا على الأدوات.

### 8.2 أمثلة على معايير القبول لمتطلبات مختارة

**FR-ACC-005 (تغيير طريقة البيع):**
- Given: حساب على "تواصل" فيه إعلان بدون سعر.
- When: صاحب الحساب يغير الطريقة لـ "دفع أونلاين".
- Then: الإعلان يتخفي من الدفع، ويظهر بس للتواصل لحد ما يتعدل.

**FR-QTA-005 (تصفير الحدود):**
- Given: المستخدم وصل للحد اليومي الساعة 11:50 مساءً بتوقيت القاهرة.
- When: الساعة بقت 12:00 منتصف الليل بتوقيت القاهرة.
- Then: العداد يتصفر، والمستخدم يقدر يعمل عملية جديدة.

**FR-SRC-012 (الإعلانات غير المعتمدة):**
- Given: إعلان حالته `pending`.
- When: مستخدم يبحث عن نفس الإعلان.
- Then: الإعلان ما يظهرش في النتايج.

**FR-CHT-008 (إعادة الإرسال):**
- Given: الاتصال بالـ WebSocket اتقطع بعد ما المستخدم بعت رسالة.
- When: الاتصال رجع.
- Then: الرسالة تتبعت مرة واحدة فقط، من غير تكرار.
